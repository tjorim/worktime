# Android companion audit

[Originating issue #1192](https://github.com/tjorim/worktime/issues/1192) · [August 2026 audit](archive/android-audit-2026-08.md)

## Scope and method

Android is a companion for Today status, upcoming shifts, team status, quick time-tracking actions and reminders. Time-off management, settings and administration are deliberately web-only. The current Android app still ships Time Off and Settings destinations. Moving those workflows to the web requires a migration that preserves sign-out, device lock and Android notification permission controls.

This November 2026 audit is based on Android source, manifests, build variants, test and CI inventory, and the corresponding responsive frontend source at `4d9cbff1`. It revisits the August findings and traces current behavior from activity and navigation through view models, storage, network requests and background receivers. The scenarios below are source-derived validation cases. Neither `emulator` nor `adb` was on PATH, and device discovery reported no Android SDK or device host. No APK, device tests, screenshots, TalkBack, rendered contrast, font scaling or battery measurements were run for this report. Screen comparisons refer to declared structure and states. The product decision calls for a design-system proposal and roadmap without mockups.

## Findings and follow-ups

Severity reflects user impact: high risks exposing previous session data or losing a core companion function, medium affects recoverability or a narrower workflow, and low covers quality improvements. Kotlin paths below are relative to `android/app/src/main/java/com/worktime/android/`.

| Severity | Evidence and verification scenario | Recommended fix and tracking |
|---|---|---|
| High | `data/repository/WorktimeRepository.kt` stores a single cache entry and a mutable `currentUserId`. `core/storage/DashboardCacheStore.kt` stores the payload and timestamp without session provenance. The dashboard HTTP 401 branch clears the cache, but the token-refresh terminal path and action HTTP 401 branches can sign out without clearing it. `feature/dashboard/DashboardViewModel.kt` also retains action state after logout. ### Existing safeguards and validation gaps

- **Auth and privacy.** `core/auth/OidcSessionManager.kt` coordinates refresh with a mutex, distinguishes retryable failures from terminal invalid grants, and separates interactive end-session from local cleanup. `core/storage/SecureSessionStore.kt` uses encrypted preferences. The [manifest](../android/app/src/main/AndroidManifest.xml) disables backups. The [build configuration](../android/app/build.gradle.kts) requires release signing, API URL and pins for release artifact tasks. [Android setup](../android/README.md) describes certificate rotation and separate FCM configuration. Release signing and production FCM delivery were outside the executable evidence of this review. [#1273](https://github.com/tjorim/worktime/issues/1273) covers production FCM verification.
- **Background and restoration.** `core/notifications/ReminderScheduler.kt` restores future alarms on boot/time changes and checks persisted account identity when dispatching. `PlannedTaskReminderReconcileWorker.kt` retries transient wake fetch failures. `MainActivity.kt` passes warm notification intents to the existing navigation controller. Navigation saves tab state while the scaffold is present. The biometric gate replaces that scaffold, so switching away from Today and then locking/unlocking is a separate restoration case to check in #1237.
- **Error handling and Compose performance.** Dashboard and action jobs cancel and replace prior refreshes. Connectivity recovery and foreground SSE can trigger reloads, and a successful dashboard fetch can trigger seven action reads. The scaffold collects state per destination and shares lazy lists, but Today watches the full action snapshot. In [#2093](https://github.com/tjorim/worktime/issues/2093), measure requests on reconnect and verify that changes in labels or sync metadata do not reset in-progress task input or re-arm unrelated alarms. Use safe, actionable copy for transport and decode errors. The repository still passes generic exception messages through in several catch branches. Keep canonical API route work in [#2088](https://github.com/tjorim/worktime/issues/2088).
- **Tests and CI.** JVM suites cover auth, repository/cache, view models, SSE, pinning and reminder logic. [Instrumented sources](../android/app/src/androidTest/) cover navigation, Today, the Time Off form and changelog. [Android CI](../.github/workflows/android.yml) runs an API 34 emulator and uploads test reports. Extend the suites under each fix with the failure scenarios above. Full-screen captures, process recreation, TalkBack and permission transitions belong in the existing device pass. The August report predates these CI and navigation improvements.

## Web and Android capability and UX matrix

Web evidence comes from [Status](../frontend/src/features/status/), [Schedule](../frontend/src/features/schedule/), [Time tracking](../frontend/src/features/time-tracking/), [Time off](../frontend/src/features/time-off/) and [Settings](../frontend/src/features/settings/). Android behavior comes from the route and component sources named above.

| Experience | Responsive web | Android today and direction | Classification |
|---|---|---|---|
| Today and current shift | Status and schedule context | Today uses summary cards and coloured shift badges. Keep the same date, shift, active/off-day meaning and permissions. | Required product parity |
| Upcoming shifts | Schedule and calendar views | Next shows cards and an explicit empty state. Keep dates, local times and shift codes consistent. | Required product parity |
| Team status | Team/roster context | Team shows team cards with working state and shift code. Match active-state meaning and distinguish missing roster from no results. | Required product parity |
| Quick time tracking | Running timer and richer daily editing | Today offers Start/Stop/Update and quick work-location actions. Make busy, saved, failed and uncertain timer states explicit. | Required product parity |
| Reminders and permission denial | Browser notification and push controls | Android channels, alarms and Today deep links suit device delivery. Give denial an explanation and a link to system settings. | Better expressed with a native Android pattern |
| Sign-in, signed-out, locked | Web OIDC and account flows | AppAuth and biometric/device credential gate. Give loading and expiry separate recovery paths. | Better expressed with a native Android pattern |
| Loading, empty, error, offline and stale | Per-view loading, status and sync feedback | Shared state panes on Today, Next and Team. Preserve last-known data with visible freshness and contextual retry. | Required product parity |
| Navigation and system theme | Responsive web navigation and theme preference | Bottom tabs for Today, Next and Team. Follow system light/dark and use native back and restored tab state. | Better expressed with a native Android pattern |
| Time-off management and forms | Summary, creation, editing, validation and deletion | Native tab and dialogs still exist. Route management to the web. | Deliberately web-only |
| Settings, administration and destructive account actions | Settings sections, roles and confirmations | Native settings and account-deletion confirmation exist. Move product controls to web and keep essential native session/device affordances. | Deliberately web-only |
| Detailed time-tracking history, charts and bulk editing | Daily and weekly views and reporting | Companion centres on quick actions. Assess demand and offline requirements before approving expanded editing. | Deferred pending a product decision |

## Proposed Android design system

- **Colour.** Keep Worktime primary/on-primary and shift badge background/foreground pairs from `ui/theme/`. Use Material surface/on-surface, surface variant and outline for hierarchy in both themes. Define warning and error roles independently and pair shift and status colour with text.
- **Type and spacing.** Use Material headline for one semantic screen title, title for cards, body for content and label for badges or secondary metadata. Keep 4/8/12/16/24 dp spacing, flexible line heights and 48 dp minimum touch areas. Let dense rows wrap at large font sizes.
- **Shape and components.** Use existing Material card shapes, pill badges and native dialogs. Share a status summary, schedule row, timer action group, and a state panel with optional retry. Place confirmations next to the action and reserve destructive styling for irreversible actions.
- **Icons and states.** Use one Material icon family. An icon-only control needs an action label. An icon alongside equivalent visible text is decorative. Distinguish initial loading, empty results, stale success and failed refresh. Announce important action outcomes and align the visible focus order with the reading order. Keep lock and permission states actionable.

## Roadmap

1. Protect the session boundary and first-frame lock decision. Address [#2092](https://github.com/tjorim/worktime/issues/2092) and [#2094](https://github.com/tjorim/worktime/issues/2094) before expanding companion workflows.
2. Make timer status and reminder reconciliation trustworthy during intermittent connectivity. Land [#2093](https://github.com/tjorim/worktime/issues/2093) and [#2095](https://github.com/tjorim/worktime/issues/2095), then verify production delivery under #1273.
3. Implement the companion scope through [#2097](https://github.com/tjorim/worktime/issues/2097). Apply the shared state and accessibility patterns through [#2096](https://github.com/tjorim/worktime/issues/2096) as the three primary destinations settle.
4. Execute [#1237](https://github.com/tjorim/worktime/issues/1237) using a compact phone and a larger reference phone in light and dark. Capture login (initial, in-progress, cancelled/error), lock (idle, prompt, unavailable), Today (working, off-day, timer states, location/editor dialogs, success/failure), Next and Team (populated/empty), and each shared loading/error/stale state. Capture current legacy Time Off and Settings sections and dialogs while shipped, plus permission denial and notification entry. Repeat the core paths at 200% font size with TalkBack, after rotation/process recreation, and offline/online. Collect a request count during reconnect and compare it with a normal foreground refresh.
